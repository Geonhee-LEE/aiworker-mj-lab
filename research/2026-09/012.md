# 012 — R-F-009: IK 시딩 개선 문헌 확인 — reachability map 재사용 가능성

_2026-09-12 · researcher cycle_

`STATE.md` 현재 병목은 여전히 PR 리뷰 큐 포화(#13/#14/#15/#16, `gh pr
list`로 재확인 — 6일째 그대로, 신규 PR 없음)라 executor는 다음 cycle도
`EXECUTOR_SKIP`할 가능성이 높다. 기존 research 로그(001~011)를 훑어보니
후보 주제 목록(RRT 계열 튜닝, 관절공간 충돌 가속, MuJoCo 충돌 API,

가치가 낮다고 판단해, PRD에 "계획, 미착수"로 남아 있는 **R-F-009(IK 목표
탐색 개선)**를 이번 cycle 주제로 잡았다.

## 코드 확인

`scripts/demo_plan_right_arm.py:420` `_solve_valid_ik`는 PRD 설명 그대로다:
`q_init`(현재 자세)을 최우선 시도하고, 실패하면 `rng.uniform(joint_ranges)`로
**관절 전체 범위에서 균등 무작위** 시드를 최대 25회 재시도한다. 구조화된
정보(이전 성공 해, reachability 격자)는 전혀 쓰지 않는다.

이미 존재하는 `planning/reachability.py`(R-F-011, P7.0)는 베이스 프레임
격자마다 **성공률 스칼라만** 저장한다(`ReachabilityMap.success_rate`) —
성공한 `q` 자체는 버려진다. 즉 지금 형태로는 R-F-009의 시드 소스로 바로
쓸 수 없고, 격자 생성 시(`_ik_attempt` 호출부) 성공한 `q` 하나를
`representative_q`로 같이 저장하도록 확장해야 재사용 가능하다.

## 문헌 확인

1. **Warm-start (temporal coherency)**: 연속된 IK 질의 사이 목표가 조금씩만
   바뀌는 경우(마우스 드래그형 인터랙티브 데모가 정확히 이 패턴), 이전
   프레임의 해를 다음 프레임 시드로 재사용하면 반복 수가 크게 줄고 성공률이
   높아진다는 게 반복적으로 보고된다. `_solve_valid_ik`는 이미 `q_init`
   (현재 자세)을 첫 시도로 쓰므로 **이 부분은 이미 문헌 권장 패턴과
   일치** — 신규 조치 불필요.
2. **구조화된 재시도 시드 (reachability/grid 기반) vs 순수 무작위**: 여러
   문헌이 "무작위로 시드를 고르는 대신 reachability map이나 인접 격자에서
   뽑은 시드를 쓰면 불필요한 계산을 줄인다"고 일관되게 보고한다 — 이게
   정확히 R-F-009가 지목한 개선 방향이다. 실패 시 무작위 폴백은 유지하되,
   **첫 몇 번의 재시도를 목표 근처(현재 자세 반경 내 축소 샘플링, 또는
   reachability map의 인접 성공 격자에서 가져온 시드)로 편향**시키는 방식이
   구현 비용 대비 이득이 커 보인다.
3. 신경망 기반 warm-start(GNN 등)는 이 저장소 규모(오른팔 7-DOF, 학습 기반
   플래너는 PRD 비-목표)에 맞지 않아 후보에서 제외.

## 이 저장소에 대한 판단

`n_restarts=25` 전체를 구조화 샘플링으로 바꾸는 큰 변경보다, 두 단계로
쪼갤 수 있는 작은 개선이 "+50 LOC 이상엔 측정 가능 이득 1개" 원칙에
맞다:

- **1차 후보(즉시 착수 가능, 신규 모듈 불필요)**: 균등 무작위 대신
  `q_init` 주변 반경을 단계적으로 넓히는(예: 관절범위의 10% → 30% → 100%)
  샘플링으로 바꾸기만 해도, "현재 자세에서 크게 벗어나지 않는 해"를 더
  빨리 찾을 확률이 높다(nullspace 정칙화 목표와도 방향이 같다). 새 데이터
  구조 없이 `_solve_valid_ik` 내부 샘플링 한 줄만 바뀐다.
- **2차 후보(R-F-011 확장 필요, 더 큰 변경)**: `ReachabilityMap`이
  `representative_q`까지 저장하도록 확장하고, `_solve_valid_ik`가 목표
  위치 근처 격자의 저장된 `q`를 시드 후보에 추가. 이건 R-F-011 재사용
  원칙(§7)에 맞지만 스키마 변경이라 P7 쪽 기존 PR(#10, 이미 병합)과의
  하위호환도 고려해야 해서 1차보다 비용이 크다.
