# 009 — clearance()가 쓰지도 않는 Jacobian을 매 쌍마다 계산한다

_2026-09-09 · researcher cycle_

## 배경

PRD 조사 지시 후보 중 "MuJoCo `mj_collision`/`mj_geomDistance` 활용 사례"를
따라가려고 실제 구현부터 다시 읽었다(`src/ffw_sh5_grasp/planning/collision_state.py`,
`src/ffw_sh5_grasp/kinematics/collision.py`). 병목은 PR 리뷰 큐가 4건으로
포화된 상태(STATE.md)라 신규 설계보다 기존 코드의 실측 가능한 낭비를 찾는
쪽으로 스코프를 좁혔다.

## 발견

`ArmCollisionChecker.is_valid`(빠른 boolean 경로)는 이미 최적이다 —
`mj_kinematics` + `mj_collision`(broad+narrow phase, geom_margin 부풀리기)만
쓰고 어떤 Jacobian도 계산하지 않는다(`collision_state.py:175-187`).

문제는 `ArmCollisionChecker.clearance()`다(`collision_state.py:201-219`,
docstring 스스로 "``is_valid``보다 훨씬 비싸다"라고 명시). 이 메서드는
등록된 모든 `CollisionPair`(`kinematics/collision.py`의
`default_collision_pairs`, 이 로봇 모델 기준 대략 수십 쌍)에 대해
`collision_distance_gradient`를 호출하는데, 이 함수의 세 모드
(`geom`/`table_top`/`bounding_sphere`) 전부가 **무조건** `tree.point_jacobian`을
쌍마다 2회(`jacobian_a`, `jacobian_b`) 호출해 `CollisionConstraint.gradient`를
채운다(`collision.py:92-98`, `:224-234`, `:271-277`). 그런데 호출부인
`clearance()`는 반환된 `constraint.distance`만 읽고 `constraint.gradient`는
그 자리에서 버린다(`collision_state.py:216-218`) — whole-body IK의 CBF
경로(`control.whole_body`)만 gradient가 실제로 필요하다.

`tree.point_jacobian`은 활성 관절 수에 비례한 기구학 트리 순회이므로
`mj_geomDistance` 단독 호출(narrow-phase geometry 쿼리, gradient 없음)보다
훨씬 무겁다. 즉 `clearance()`가 벤치마크/테스트에서 매 seed·매 waypoint마다
지불하는 비용의 상당 부분이 **호출부가 쓰지도 않는 계산**이다.

곁가지로 WebSearch에서 MuJoCo 저장소의 최근 PR
[google-deepmind/mujoco#2689](https://github.com/google-deepmind/mujoco/pull/2689)
(`geom_distance_utils.py`, 미병합 초안)를 발견 — `mj_geomDistance`가 매
호출마다 버퍼를 새로 할당하는 오버헤드가 있어 얇은 wrapper로 버퍼를
재사용하자는 제안이다. 이 저장소의 `collision_distance_gradient`도
`np.zeros(6)`(`fromto` 버퍼)를 매 호출 새로 할당한다(`collision.py:57`) —
Jacobian 생략만큼 크지는 않지만 같은 방향의 부수적 낭비.

## 이 프로젝트와의 연결

- MP-0028(safety-certificate 캐싱 순이득 프로파일링, PR #15 리뷰 대기)의
  결론 "`clearance()`가 `is_valid()`보다 훨씬 비싸 순이득이 반경≫resolution일
  때만 나온다"는 **이 낭비가 포함된 `clearance()` 비용을 기준선으로 측정한
  결과일 가능성이 높다.** Jacobian 생략으로 `clearance()` 자체를 먼저
  가볍게 만들면 safety-certificate 캐싱의 순이득 판단이 달라질 수 있다 —
  다만 이건 PR #15가 병합되고 재프로파일링해야 확인 가능하므로 지금은
  가설로만 기록한다.
- `tests/test_planning_execution.py`(R-NF 실행 안전성, 재생 중 최소 clearance
  검증)와 `scripts/benchmark_planning.py`가 둘 다 `clearance()`를 반복
  호출하므로, 이 최적화는 벤치마크 완주 시간(R-F-006, 2분 이내 요구)에도
  직접 도움이 된다.

## 제안

`collision_distance_gradient`에 `need_gradient: bool = True` 키워드를 추가해
`False`일 때 세 모드 모두 `tree.point_jacobian` 호출 두 번을 건너뛰고
`CollisionConstraint.gradient`에 `None`(또는 빈 배열)을 채워 반환한다.
`clearance()`는 `need_gradient=False`로 호출하도록 한 줄만 바꾼다. 기존
whole-body IK CBF 호출부(gradient 필요)는 기본값 `True`를 그대로 쓰므로
API 변경이 없다. 새 알고리즘이 아니라 기존 함수에 조기 반환 분기 하나를
추가하는 수준이라 §7 기존 자산 재사용 원칙과도 맞는다.
